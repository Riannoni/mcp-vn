# Архитектура mcp-vn 0.6.4

Этот документ описывает **текущую реализацию**, а не исторические версии v4–v6.3. Основные исходники: `server.mjs`, `src/`, `worker/`, `web/`, `deploy/`.

## Компоненты и границы данных

| Компонент | Где работает | Назначение |
| --- | --- | --- |
| ChatGPT / MCP Apps | клиент | Главное повествование, отрисовка UI, вызовы инструментов |
| VPS с авторизацией | отдельный узел | Проверка OAuth/JWT, защищённый публичный Streamable HTTP MCP, не занимается диффузией |
| `mcp-vn` | домашний Docker, Node 22 | Правила игры, сохранения, очередь, защищённая раздача ассетов, память и локальный эпизод |
| `mcp-vn-worker` | игровой ПК | Получает задания по pull API, строит схемы ComfyUI, принимает ответы QA, публикует результат |
| ComfyUI | ПК, ROCm | SDXL/Pony, WAI-Illustrious, Anima, Wan 2.2 |
| Vision QA | ПК, CPU | CLIP и локальная VLM для базовых проверок локации, количества персонажей и отдельных атрибутов |
| KoboldCpp gateway | ПК, ROCm / CPU | Cydonia и Qwen по защищённому LAN API, запуск по запросу, fallback при сбое |
| Model Lab | отдельный локальный UI | Независимое сравнение моделей; **исходники этой панели не входят в этот репозиторий** |

Игровые данные в `data/` примонтированы в контейнер как `/data`. Директории: `games/` — состояние игры, `stories/` — импортированные истории, `jobs/` — очередь, `assets/` — изображения/видео, `local-scenes/` — отдельные локальные эпизоды. Каталог исключён из Git.

### Основной сюжет

```text
UI → submit_action_fast → атомарная запись действия
   → компактный narration_packet → ChatGPT
   → gm_continue_fast (один commit истории)
   → get_live_delta / wait_for_game_events
   → история, обновления локации, фона и слоёв
```

Игрок управляет только героем. Рассказчик не должен сам придумывать его решения или повторно отправлять `submit_action_fast` для уже принятого действия. Ход сохраняется до генерации картинки; художественная очередь не должна задерживать текстовую историю.

Память и правила: `src/story-memory.mjs`, `src/game-rules.mjs`, `src/narration-packet.mjs`. Кэши основных локаций и вариантов спрайтов: `src/scene-cache.mjs`, `src/visual-state.mjs`.

### Локальный эпизод

```text
UI → local_turn_submit → отдельный журнал
   → Cydonia 24B (только реплики NPC)
      └── Qwen 9B при ошибке/неудачной попытке
   → сохранение текста → Qwen 9B visual director JSON
   → render-policy.mjs (none / sprite / cg)
       ├── none: без GPU, сохранение картинки
       ├── sprite: вариант только изменённого персонажа
       └── cg: цельный neural CG без предварительных дублирующих спрайтов
   → локальная QA, превью в отдельной сцене
```

Локальные реплики в `data/local-scenes` не становятся обычными сообщениями `data/games` и не передаются в обычный контекст ChatGPT; при возврате в основной сюжет используется предусмотренный нейтральный мост. При закрытии режима канонические CG, спрайты и фон не перезаписываются.

Точки интеграции: `src/local-scene.mjs`, `src/local-narrator.mjs`, `src/local-director.mjs`, `src/render-policy.mjs`, `src/gpu-coordinator.mjs`.

## Система изображений

**Не смешивайте две стратегии:**

1. **Каноническая layered-сцена:** отдельный фон + прозрачные спрайты. Фон и варианты спрайтов кэшируются. Канонический composite CG собирается из принятых спрайтов и остаётся отдельным ассетом.
2. **Локальный neural CG:** единый кадр с опорой на закреплённые лица и текущий визуальный state. Создаётся только для существенного события, а не на каждом диалоге. Старые индивидуальные предварительные спрайты не обязательны и больше не создаются перед каждым CG.

При выборе нового CG учитываются действия и физические изменения **в подтверждённом тексте NPC**, а не только запрос игрока. Режим определяется объяснимыми правилами. Директор не может один своим `render:true` заставить видеокарту работать без значимого изменения состояния.

### Референсы

`identities[name]` содержит закреплённый первый принятый образ, `face_url` и вариации. Для SDXL/Pony/WAI региональные IPAdapter-референсы помогают удерживать разных персонажей в одном кадре. Полноростные спрайты диалога служат визуальными слоями, но не необходимыми зависимостями CG.

Anima использует другой UNET, CLIP и VAE, поэтому SDXL-only IPAdapter/ControlNet нельзя применять к ней напрямую. Её консистентность зависит от описаний и доступной img2img-преемственности.

### Объяснимый выбор рендера

| Условие | Действие |
| --- | --- |
| Ничего визуально не поменялось | `none`, прежний кадр |
| Лёгкая эмоция при отображении CG | `none`, не заменять цельный CG на несогласованные спрайты |
| Изменение выражения лица в layered-сцене | `sprite`, только нужный персонаж, с кэшем |
| Перемещение спрайта слева направо | Перестановка DOM, без GPU |
| Контакт тел, заметная поза, новая одежда, локация | `cg`, единый кадр |
| Пользователь явно запросил другой ракурс | `cg` |
| Ручная повторная генерация CG | Пропуск cache-hit, новое задание |

Подробные поля `visual_decision`, сигнатуры, QA и условия повторного использования: [RENDER-POLICY-v64.md](RENDER-POLICY-v64.md).

## Очередь и QA

`src/jobs.mjs` создаёт неизменяемый снимок входных условий (`src/art-spec.mjs`), отмечает статус `queued/working/done/failed/superseded` и не устанавливает результат уже устаревшей сцены. Воркер сообщает стадии и тайминги, а сервер проверяет геометрию и подписи ассетов при публикации.

`worker/vision_daemon.py` и `src/local-visual-qa.mjs` отсеивают ряд очевидных ошибок состава и локации. Их verdict **не доказывает** корректную анатомию, точный физический контакт или положение одежды; для важных сцен нужна визуальная проверка человеком.

## Кэш и память

- Кэш фонов: место, время суток, погода, стиль.
- Варианты спрайтов: имя, стиль, одежда, поза, эмоция, фон.
- Приватные CG: SHA-256 от физического состояния, камеры, локации, актёров и стиля; результат повторно используется только после завершения и существующей независимой QA.
- RAM на ПК: до 128 МиБ immutable bytes референсов, LRU (`VN_ASSET_CACHE_MIB`), без потери качества пикселей. Это сокращает чтение/передачу, а не время диффузии.
- LLM: модели запускаются и выгружаются по запросу; не держим Cydonia горячей параллельно с ComfyUI на одной 16 ГБ видеокарте.

## Экран

Широкие фоны и канонический CG остаются landscape, а локальные event CG — 896×1152 portrait. По умолчанию `object-fit:contain`, с возможностью `cover` для заполнения. UI сохраняет два режима отображения изображения без перезаписи оригинала.

## Технические ограничения

Система оптимизирована для **одной** AMD GPU и одного персонального развёртывания. Общая GPU-координация предотвращает ряд конфликтов, но не является аппаратной изоляцией. Переключение моделей, загрузка SDXL-весов, VLM-проверки и WAN-видео остаются затратными.

Последний подтверждённый тест сборки: 98/98 Node-тестов, 5/5 scene-grounding, 3/3 visual-contract, 2/2 RAM-cache. Точные инструкции по проверке и откату — [OPERATIONS.md](OPERATIONS.md).
