# Scene interaction QA: map held in both hands (isolated A/B, 2026-10-30)

Status: **experimental diagnostic only, no publish and NO-GO for visual acceptance**.
Read `AGENTS.md` -> `docs/DEVELOPMENT-AND-TESTING.md` on `main`.

## First structural A/B

The immutable accepted character sprite and accepted outdoor market backdrop
were combined privately, with the canonical head removed from the editable
region. This preserved the same person when the model changed the lower image.
All three tests used native FLUX.2 Klein, the same source scene, same seed
2026103062, one GPU execution each, and no retries within a test:

- Full foreground mask: 8.05s. SFace canonical identity 0.85573, background
  continuity preserved, but giant map hid hand interactions and lower body
  was deformed. **G2 FAIL**.
- Restrict editable area to the upper body only: 4.01s. SFace 0.85726 and
  lower body preserved; map still hid critical hand interaction. **G2 FAIL**.
- Same restricted mask, changed only prop-size/grip instruction: 4.01s.
  Face retained and map better centered. However DWPose finger centers were
  (0.6045,0.5020) and (0.4539,0.6757), while independent Florence-2 placed
  map at (0.3844,0.3748,0.6344,0.6595) normalized. The second hand's
  fingertips fall below the map edge. Florence's descriptive caption said
  "holding a map" but is not proof of a two-hand grip. **G2 FAIL**.

The `worker/map_grip_evidence.py` diagnostic is a deliberately conservative
spatial cross-check: both hands need sufficiently observed DWPose fingers,
separate left/right map edges and an independent Florence map box and caption.
It returns at most `plausible` and cannot set QA `passed` or prove physical
contact. It returned `unobservable` on the third actual GPU frame with reason
`one_or_both_hands_not_on_map_edges`. Unit tests include false-positive
checks for a hand below the map and missing attribution. Original game state
was read-only; all private output remains outside the playable game's assets.

## Next structural requirement

Stop changing masks/prompts for this defect. The generator needs a **typed
interaction blocking plan**: actor's left/right hand target locations,
object bounding box, body and camera constraints and an approved pose guide.
The object should be made at a controlled scale, and a relation verifier must
not conflate an object being present with its being held in two hands.
Never turn `plausible/unobservable` into `verified` just to close this issue.

A human-labeled positive and negative set, independent view-specific identity
and preservation of one source-state fingerprint are required before the
first-attempt 1 sprite + 3 CG milestone can be accepted. Do not merge into
production simply because G1 image generation succeeded.
