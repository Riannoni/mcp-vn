# Эксплуатация и восстановление mcp-vn 0.6.4

## Быстрая проверка состояния

На домашнем сервере:

```bash
cd /opt/mcp-vn
docker compose ps
docker compose logs --tail=100 game
curl -fsS http://HOME_SERVER_LAN_IP:3100/healthz
# Ожидаемый ответ: {"ok":true,"name":"mcp-vn","version":"0.6.4"}
```

На Bazzite ПК:

```bash
systemctl --user is-active mcp-vn-worker.service
systemctl --user is-active mcp-vn-comfy.service
systemctl --user is-active mcp-vn-vision.service
systemctl --user is-active mcp-vn-kobold-gateway.service
curl -fsS http://127.0.0.1:8188/queue
journalctl --user -u mcp-vn-worker.service -n 100 --no-pager
journalctl --user -u mcp-vn-comfy.service -n 100 --no-pager
journalctl --user -u mcp-vn-kobold-gateway.service -n 100 --no-pager
```

Не публикуйте эти журналы без проверки: ошибки могут содержать текст пользовательского задания и локальные пути.

## Автоматические тесты

На домашнем сервере:

```bash
cd /opt/mcp-vn
docker compose build game        # сборка + 98 Node tests
python3 tests/scene-grounding.test.py
python3 tests/visual-contract.test.py
git diff --check
```

На ПК с соответствующим Python и установленными модулями:

```bash
python3 /path/to/tests/worker-asset-cache.test.py
python3 /path/to/tests/worker-style-graphs.test.py
python3 /path/to/tests/pc-kobold-backends.test.py
```

Часть тестов импортирует локально установленный воркер или шлюз, поэтому её нужно запускать там, где реально находятся их модули/venv. **Не** запускайте произвольные CG-рендеры во время активной игровой генерации: на GPU одна очередь.

Базовая проверка v6.4: 98/98 Node, 5/5 scene-grounding, 3/3 visual-contract, 2/2 reference RAM-cache. Отдельный тест CG 896×1152 на Pony завершился за ~13 с. Данные тесты проверяют механику; точность поз и сложных взаимодействий требуют визуальной оценки.

## Обновление игры

Сначала сохраните `data/` и приватную `.env` во внешнее, защищённое от посторонних место. Убедитесь, что нет незаконченного сюжетного хода и активных GPU-задач.

```bash
cd /opt/mcp-vn
git status
git fetch origin
git pull --ff-only origin main
docker compose build game
docker compose up -d --no-deps game
curl -fsS http://HOME_SERVER_LAN_IP:3100/healthz
```

Если менялась `worker/worker.py`, синхронизируйте файл с ПК, проверьте `python3 -m py_compile worker.py` и перезапустите **только** `mcp-vn-worker.service`. Перезапускайте KoboldCpp/ComfyUI лишь при изменении их конфигурации. Операции с GPU делайте после завершения текущих заданий.

## Резервные копии

Данные хранятся в `/opt/mcp-vn/data/` — там находятся личные истории, сохранения, локальные эпизоды, фотографии/CG и логика выполненных ходов. Делайте резервные копии **всего каталога**, сохраняя владельца и права доступа. Пример для ручного обслуживания:

```bash
cd /opt
sudo tar -czf /PRIVATE_BACKUP_LOCATION/mcp-vn-data-$(date +%Y%m%d-%H%M).tgz \
  mcp-vn/data
```

Приватный `/opt/mcp-vn/.env` и секреты ПК резервируйте отдельно в защищённом хранилище. Не переносите их в Git.

**Нельзя** восстанавливать старую копию сохранения поверх более нового без отдельного подтверждения: это уничтожит недавние ходы. Для отката *кода* сохранения менять не требуется.

## Частые проблемы

| Симптом | Проверка |
| --- | --- |
| Контейнер постоянно перезапускается | `docker compose logs game`; в прошлой сборке причина была `EACCES` на новом исходном модуле, запущенном под `node`. Проверяйте режим 0644 у файлов JS, скопированных в образ. |
| ChatGPT показывает устаревший UI | Обновите соединение с MCP-приложением и вызовите `open_game_v64`. Старые ключи UI могут быть закэшированы клиентом. |
| Нет картинки при готовом сюжете | Статусы `list_art_jobs_ui`, очередь ComfyUI, `mcp-vn-worker`, QA-ошибки и доступ к подписанному URL ассета. |
| CG обрезан в боковой панели | В v6.4 по умолчанию `Fit/contain`; проверьте режим «Заполнить», масштаб браузера и старый UI. |
| Спрайт не обновился | Сравните `desired_variant_key` и `rendered_variant_key`; проверка фона/состояния может пометить образ как устаревший. |
| Для каждого текста создаётся CG | Проверьте `visual_decision.mode` / `reason` и `src/render-policy.mjs`. Не доверяйте только JSON `render:true` визуального директора. |
| Неуместный или неверный CG | Посмотрите QA и предупреждения в задании. Проверка персонажей/локации не доказывает точную позу или действие; используйте ручной пересогласованный кадр. |
| Cydonia/Qwen ответили медленно | `local_model_health`, ROCm/CPU backend, очередь GPU и длительность холодной загрузки. Cydonia значительно тяжелее Qwen. |
| AMD GPU сбрасывает вычислительную очередь | Не возвращайте старый Vulkan без тестов. Используйте проверенный ROCm gateway и CPU fallback. См. `LOCAL-LLM-ROCM.md`. |
| Отказ в доступе к публичному MCP | Для анонимного запроса 401 штатен. Проверьте OAuth/JWT, VPS маршрут и источник токена; **не** отключайте авторизацию. |

## Кэш и загрузка ресурсов

Кэш фонов, спрайтов и одобренных CG связан с конкретным сохранением и идентичностью сцены. Невозможно безопасно повторно использовать CG при другой позе, одежде, окружении или актёрах. Для каждого хода `local_episode_status.visual_decision` содержит режим, причину и признак повторного использования.

RAM-кэш worker хранит только байты неизменных референсов, по умолчанию 128 МиБ. Измените `VN_ASSET_CACHE_MIB` (0–256) в приватном worker env только если это оправдано измерениями. Веса больших моделей лучше не копировать в tmpfs; RAM-offload обычно помогает вместить модель, а не ускорить диффузию.

## Откат

Откатить исходники можно на предыдущий проверенный коммит, но не переписывайте сохранения. Перед изменением `main` проверьте `git log` и соберите старый Docker image. Последняя локальная v6.4 реализация отмечена коммитом `fb94f06` в первоначальной ветке разработки; после публикации актуальная ветка GitHub может иметь другой SHA, если история синхронизирована одним снимком.

Резервная копия перед v6.4: `/opt/mcp-vn-backups/pre-v64-deploy-20261028T110312Z/`. Она содержит **старое** состояние игры и нужна только для аварийного восстановления с осознанием потери прогресса.

Резервный PC worker: `~/.local/share/mcp-vn/worker.py.backup-v64-router`. Перед восстановлением проверяйте несовместимость старого воркера с новой схемой `art-spec`.

Отдельно сохраняйте работающие настройки gateway и ComfyUI; при проблемах локального текста переключите `VN_KOBOLD_CPU_ONLY=1` (инструкция в [LOCAL-LLM-ROCM.md](LOCAL-LLM-ROCM.md)).

## Для разработки

Перед публикацией:

1. Не должно быть незавершённого хода игрока и фоновых задач, которые будут затронуты перезапуском.
2. `npm test` и Python QA должны пройти; Vite output не публикуется в Git.
3. Отсутствуют изменённые `.env`, `data/`, веса `.safetensors`/`.gguf`, ключи и приватные диалоги.
4. После деплоя подтвердить `/healthz`, модельный backend и отображение одного сохранения; не менять его сюжет для smoke-test.
5. Закоммитить документацию совместно с изменением кода и проверить актуальность версии на виджете ChatGPT.
