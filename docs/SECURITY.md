# Безопасность и приватность mcp-vn

Репозиторий [Riannoni/mcp-vn](https://github.com/Riannoni/web-vn) — **публичный**. В нём находятся исходники и примеры настроек, **не** секреты, данные игроков или модели.

## Что разрешено хранить в Git

- Node/JS, Python, Dockerfile, шаблоны сервисов и нейтральные тестовые файлы.
- `.env.example` и `deploy/worker.env.example` с заведомо недействительными placeholder-значениями.
- Схемы ComfyUI, документация по архитектуре, пути к моделям без самих весов.
- Контрольные суммы **публичных** бинарных релизов (но не сами файлы и не частные скачивания).

## Что нельзя публиковать

| Данные | Где должны храниться |
| --- | --- |
| `VN_MCP_TOKEN`, `VN_WORKER_TOKEN`, `VN_ASSET_SECRET` | приватная `.env` домашнего сервера |
| `VN_LOCAL_ROUTER_TOKEN` | приватный systemd EnvironmentFile на ПК |
| OAuth/Auth0 private keys, client secrets, JWT, API credentials | секретное хранилище/VPS |
| SSH ключи и сертификаты | только на соответствующих узлах |
| `data/games`, `data/local-scenes`, `data/assets` | локальная защищённая папка данных, вне Git |
| Model weights (`.safetensors`, `.gguf`), PNG/MP4 сцен, face refs | собственный диск ПК/домашнего сервера |
| Подробные приватные сюжетные диалоги/тестовые промпты | внутренняя игровая БД/закрытые логи |

Для сохранений и приватных эпизодов не используйте публичные CI artifacts. Временные отладочные файлы перед коммитом удаляйте или явно исключайте из Git.

## Уровни доступа

- Публичный MCP доступен через **HTTPS + OAuth/JWT gateway**; отсутствие OAuth должно возвращать отказ доступа. Не использовать insecure anonymous mode.
- Home game сервер принимает только доверенные MCP и worker запросы с раздельными секретами. Не выставлять `:3100` в публичный Интернет без проверенного gateway.
- ComfyUI, Vision QA и внутренний endpoint KoboldCpp должны оставаться на loopback ПК или в защищённой локальной сети.
- Подписанные ссылки на ассеты не заменяют проверку авторизации на служебных API.
- Обращение к частным локальным эпизодам требует подтверждённого допуска совершеннолетних персонажей; детали локального эпизода хранятся отдельно от канонических сообщений главного GM.

## Git hygiene

```bash
cd /opt/mcp-vn
git status --short
git diff --check
git ls-files | grep -E '(^data/|^\\.env$|\\.pem$|\\.key$|\\.safetensors$|\\.gguf$)' \
  && echo 'CHECK TRACKED FILES BEFORE PUSH'
```

`.gitignore` исключает `.env`, `data/`, `node_modules/`, `dist/`, Python cache и служебные backup/log files. Однако **игнорирование не удаляет файл, который уже попадал в историю Git**. При случайной публикации секрета нужно немедленно отозвать/сменить его, а затем отдельно очищать историю.

В публичных инструкциях используйте `YOUR_DOMAIN`/`HOME_SERVER_LAN_IP`. Исходное `compose.yaml` содержит сетевые привязки персональной установки, поэтому при клонировании на другой хост его нужно адаптировать. IP-адреса сами по себе не являются ключами, но раскрывают детали топологии, и их лучше не добавлять в новые примеры.

## Модели и данные

Веса community-моделей имеют собственные лицензии. Не встраивайте их в публичный репозиторий без проверки разрешений авторов. Разделяйте:

- локальные образы и текст (PC, ComfyUI/KoboldCpp);
- публично доступную авторизованную оболочку ChatGPT;
- отдельные приватные результаты локальных эпизодов;
- исходники модуля визуальной новеллы.

Использование локальной LLM не означает полной изоляции **всего** приложения от Интернета: основной сюжет по-прежнему использует ChatGPT через MCP.

## Перед публикацией релиза

1. Выполнить проверку отслеживаемых файлов на ключи, JWT и содержимое `data/`.
2. Убедиться, что вновь созданные документы не цитируют реальные приватные токены/сохранения.
3. Сверить рабочую ветку с GitHub, не делать `git push --force` без явного согласования.
4. Собрать проект и прогнать тесты.
5. Проверить, что GitHub получил ровно исходники и документацию, а не артефакты runtime.

При подозрении на компрометацию: отозвать OAuth credentials и токены, сменить `VN_*` ключи на всех узлах, перезапустить gateway и worker, проверить аудит.
